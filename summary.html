배포 모델과 소비 방식

퍼블릭 클라우드

클라우드 공급자 인프라를 여러 조직이 사용. 초기 비용이 낮고 빠르게 확장.

프라이빗 클라우드

한 조직 전용. 통제력은 높지만 비용·운영 부담도 큼.

하이브리드 클라우드

온-프레미스와 퍼블릭 클라우드를 연결. 규제·점진적 이전에 적합.

CapEx → OpEx서버를 미리 구매하지 않고 사용량에 따라 지불. 수요 변화에 맞춰 비용도 변한다.

IaaS · PaaS · SaaS

유형고객이 주로 관리대표 예선택 기준
IaaSOS, 앱, 데이터Azure Virtual Machines제어권·기존 앱 호환
PaaS앱과 데이터Azure App Service, Azure SQL Database인프라 대신 개발에 집중
SaaS사용자·데이터·설정Microsoft 365완성된 소프트웨어 사용
공유 책임 함정물리 보안은 항상 공급자 책임. IaaS에서는 고객의 OS 책임이 크고 SaaS로 갈수록 공급자 책임이 커진다. 데이터·ID·계정 책임은 사라지지 않는다.

시험 단골 용어

  • 고가용성: 장애 중에도 서비스가 사용 가능한 상태
  • 확장성: 부하에 맞춰 수직(성능) 또는 수평(수량) 확장
  • 탄력성: 수요에 따라 자동으로 자원을 늘리고 줄이는 능력
  • 신뢰성: 장애 복구와 분산 설계로 일관되게 동작
  • 서버리스: 서버 관리 없이 이벤트 기반 실행, 실행량 중심 과금

Azure 아키텍처와 서비스

범위와 계층

관리 그룹›구독›리소스 그룹›리소스
  • 리전: 지연 시간 경계 안의 하나 이상 데이터센터 집합
  • 가용성 영역: 리전 안에서 전원·냉각·네트워크가 독립된 물리 위치
  • 리소스 그룹: 함께 관리할 리소스의 논리 컨테이너. 리소스는 한 번에 하나에만 속함
  • 구독: 청구 및 액세스 관리 경계. 관리 그룹으로 여러 구독에 정책 적용

컴퓨팅 선택

Virtual Machines

OS 제어, 레거시 앱, 사용자 지정 소프트웨어. 관리 부담 최대.

App Service

웹 앱·API용 PaaS. OS 관리 없이 배포·자동 확장.

Azure Functions

짧은 이벤트 기반 코드. 서버리스·실행 기반 과금.

Containers

가볍고 이식 가능한 패키지. OS 커널을 공유.

VM Scale Sets

동일 VM 집합을 자동 확장하고 부하 분산.

Azure Virtual Desktop

클라우드에서 Windows 데스크톱·앱 제공.

이미지·영상·백업 같은 비정형 개체 데이터

Managed Disks

Azure VM용 블록 스토리지

중복성LRS(한 데이터센터) → ZRS(한 리전의 영역) → GRS(보조 리전) → GZRS(영역 + 보조 리전). RA- 접두사는 보조 복제본 읽기를 허용.

Access tier: Hot(자주 접근), Cool/Cold(덜 접근), Archive(오프라인·복원 지연). 이동: AzCopy=명령줄, Storage Explorer=GUI, File Sync=온-프레미스 파일 서버 캐시, Data Box=대용량 물리 전송, Azure Migrate=서버·앱 이전 평가/마이그레이션.

관리와 거버넌스

헷갈리는 통제 도구

Azure Policy리소스가 조직 표준을 준수하도록 감사·거부·수정. “허용 지역 제한”
RBAC사용자·그룹·서비스 주체의 작업 권한을 제어. “누가 삭제 가능?”
Resource lock실수로 삭제·변경 방지. CanNotDelete 또는 ReadOnly
Tags비용·소유자 등 메타데이터 분류. 권한이나 정책을 상속하지 않음
Microsoft Purview데이터 거버넌스, 검색, 분류, 데이터 자산 이해

배포와 관리

  • Azure portal: 웹 GUI
  • Cloud Shell: 브라우저에서 Azure CLI(Bash) 또는 Azure PowerShell 사용
  • Azure Resource Manager: 인증·권한·태그·잠금을 일관되게 적용하는 관리 계층
  • ARM template / Bicep: 반복 가능하고 선언적인 IaC 배포
  • Azure Arc: Azure 밖의 서버·Kubernetes·데이터 서비스를 Azure 관리 평면으로 관리

모니터링 도구 구분

Azure Monitor

메트릭·로그·경고를 수집·분석하는 통합 플랫폼

Log Analytics

Monitor 로그에 KQL 쿼리를 실행하는 작업 영역·도구

Application Insights

애플리케이션 성능, 요청, 실패, 사용 현황 APM

Azure Advisor

비용·보안·성능·안정성·운영 우수성 권장 사항

Service Health

내 구독에 영향을 주는 장애·예정 유지관리·권고 알림

Azure Status vs Service Health전 세계 Azure 상태는 Status, 내 구독과 리소스에 미치는 개인화된 영향은 Service Health.
