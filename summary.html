IaaS · PaaS · SaaS

유형고객 책임대표 예선택 상황
IaaSOS·패치·앱·데이터·네트워크 설정Azure VM레거시 앱, OS 제어
PaaS앱·데이터·접근 설정App Service, Azure SQL Database인프라 대신 개발 집중
SaaS사용자·데이터·서비스 설정Microsoft 365, Dynamics 365완성된 소프트웨어 사용
공유 책임물리 데이터센터와 하드웨어는 항상 공급자 책임. IaaS의 게스트 OS는 고객 책임이다. SaaS에서도 데이터·계정·접근 책임은 사라지지 않는다.

이점과 용어

  • 고가용성: 장애 중에도 서비스가 사용 가능한 상태
  • 내결함성: 일부 구성 요소가 고장 나도 계속 동작
  • 재해 복구: 대규모 장애 후 다른 위치에서 복구
  • 확장성: 수직(성능 증가) 또는 수평(인스턴스 증가) 확장
  • 탄력성: 수요에 따라 자동으로 늘고 줄어 비용 최적화
  • 민첩성: 요구 변화에 빠르게 리소스를 배포·변경
  • 서버리스: 서버 관리 없이 이벤트 기반 실행·실행량 과금

SLA 계산

직렬 종속 서비스

두 서비스가 모두 정상이어야 하면 가용성을 곱한다. 99.9% × 99.99% = 99.89001%. SLA는 속도가 아니라 가동 시간 약속이며, 미달 시 조건에 따라 서비스 크레딧을 신청한다.

Azure 아키텍처와 서비스

계층과 범위

관리 그룹›구독›리소스 그룹›리소스
  • 관리 그룹: 여러 구독에 공통 Policy와 RBAC 적용
  • 구독: 청구와 액세스 경계, 서비스 할당량 보유
  • 리소스 그룹: 수명주기가 비슷한 리소스의 논리 컨테이너. 서로 다른 리전 포함 가능
  • 리전: 저지연 네트워크로 연결된 데이터센터 집합
  • 가용성 영역: 한 리전 안의 독립된 전원·냉각·네트워크 위치. 데이터센터 장애 대비

중복성LRS=한 위치 3복사본, ZRS=한 리전 여러 영역, GRS=보조 리전, GZRS=영역+보조 리전. RA-는 보조 복제본 읽기 허용.
